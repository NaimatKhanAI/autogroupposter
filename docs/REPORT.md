# Technical report

Implementation: commercial MV3 popup/side panel and bundled suspension-safe alarm worker; shared React customer and admin application; Firebase email/password registration, verification, reset and sign-out; group/draft/template and private image management; assigned campaigns; per-group assisted preparation and honest confirmation; backend quotas and subscriptions; revocable browser identities; mobile same-account screen; Lemon Squeezy hosted checkout/portal adapter and verified webhook ingress; security rules and tests; extension ZIP tooling.

Design follows the existing mobile teal brand. Firebase configuration is intentionally required; the app displays an explicit configuration state rather than a simulated account or successful payment.

Plan quotas count stored records, not imaginary posting volume. Campaigns and jobs are immutable snapshots of the selected content and group destinations. Unique campaign request IDs prevent duplicate creation on retries. Worker synchronization only sets a pending badge; it cannot secretly open destinations or mark publication complete. Jobs are persisted server-side and polling is replay-safe. Browser revocation prevents polling and state transitions; jobs remain visibly pending until cancelled/expired. Same-account authorization is the link mechanism; no short pairing code is needed.

The source is a substantial runnable implementation, but **the complete commercial acceptance criteria are not yet satisfied**. Required external checks: real configured Firebase Auth, deployment, provider merchant approval and sandbox checkout, portal plan changes, live browser and worker suspension tests, mobile device build and end-to-end synchronization, store review, configured policies/support identity. Additional unimplemented product scope: unified historical mobile membership/data migration, complete lifetime revenue/uptime analytics, automated deletion execution, automated reconciliation, team accounts, and Google OAuth. The owner console does include bounded invoice summaries, sanitized errors, support/deletion-request review, audit logs and release configuration with minimum-version enforcement. Account profile updates and password reset are implemented. Outstanding capabilities are not advertised as complete.

The customer site and admin are one application with backend authorization; `/admin` never confers privileges by URL. No production database, hosting or payment account was changed. Local artifacts must be configured and validated before selling subscriptions. See TESTING.md for executed results and remaining acceptance scenarios.
